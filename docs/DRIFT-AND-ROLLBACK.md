# Drift and Rollback Policy for Baseline 1.0

Baseline 1.0 has no effectiveness claim, so its implemented drift controls are data-contract checks rather than statistical production monitoring. The executable registry blocks recommendation creation when the source feature snapshot has a changed/missing/extra feature, a non-`1.0` definition version, or a non-observed epistemic tier. An operator must halt recommendation creation and investigate if an ingestion validation failure, purpose change, consent revocation, audit-read failure, registry failure, or these drift signals occur.

Rollback is deliberately simple because only one local-review model version is registered: stop the local service, preserve the immutable audit database, and disable creation of new recommendations. Existing pending recommendations can be rejected or ethics-vetoed; a terminal decision cannot be altered. A future versioned model rollback must identify the last approved registry version, restore only a verified local database backup, rerun the full automated suite, and record the human decision in the audit history.

No automatic remediation, automatic reprocessing, statistical-effectiveness claim, or autonomous production action is authorized by this policy.
